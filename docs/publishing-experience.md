# 接力卡：把填表变为核对

## 本轮已实现

发布由三步改为两步：**照片＋可选的一句话 → 同页核对、报价、交接与提交**。沿用现有视觉、物品身份和人工审核规则。

| 原来的负担 | 现在的处理 | 当前可用性 |
| --- | --- | --- |
| 上传后重新想名称和说明 | 物主原话带入名称与描述；明确写“想卖 30 元”时带入报价 | 离线规则可运行，明确说明未识图 |
| 逐项填写分类与文案 | 图片和原话一次请求生成候选名称、分类、描述 | 调用代码完成，需模型服务 |
| 系统反复追问 | 模型只返回尚缺的 function / defects / accessories，最多三项，可跳过 | 接口及选择式确认 UI 完成，待真实模型评测 |
| 额外照片占满首屏 | 侧面、缺陷与提亮收进可选区 | 已实现 |
| 交接单独占一步 | 直接在确认卡上选校门口 | 已实现 |
| 同一信息反复输入 | 回到第一步且输入不变时保留已编辑内容；缺少模型或失败时保留原话 | 已实现 |
| 历史价格看不清也要填 | 允许留空，记录为 null，详情显示“价格未知” | 已实现 |

价格仅从物主明确报价提取；原价、历史价格、多报价、万元等歧义不会自动当成当前报价。所有候选都可改，最后一次确认后才进入 REVIEW。照片无法判断的功能与缺陷不默认为“正常”或“无”。

## 为什么选择这条编排

保留 **Qwen-Agent Assistant + 单次多模态生成 + 程序校验 + 人工确认**。这是受控工作流，目前没有让模型自主决定发布或交易。将原两次串行生成合为一次，减少一次网络往返；真实速度与准确率尚未测量，不能声称性能已提高。

比较依据：

- [Qwen-Agent](https://github.com/QwenLM/Qwen-Agent) 已有视觉输入与 Assistant 调用，适合当前窄任务，不必另换框架。
- [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview) 提供持久状态、暂停恢复与人工介入。当以后增加真实账户、跨天审核、异步成交后值得重新评估；本轮不引入。
- [AgentLego OCR](https://github.com/InternLM/agentlego/tree/main/agentlego/tools/ocr) 保留为按需工具，凭证才需要 OCR；不让普通发布先经过 OCR。当前凭证表单仍是人工填写，OCR 未上线。
- [Anthropic 的工作流建议](https://www.anthropic.com/engineering/building-effective-agents) 支持先采用足够简单的方案，再根据评测增加复杂度。此处是产品实现判断，不是这些项目官方对接力卡的推荐。

## 接通模型后的课堂测试

让同学用相同照片和任务分别完成旧版与新版，记录：完成时间、输入字段数、主动操作次数、回退次数、草稿修改处数、未知信息被误填次数。不要预先填写成功率。

任务 A：照片＋“椅子，布面有磨损，想卖 30 元” → 保留磨损、报价 30，历史未知。

任务 B：只有照片 → 生成可见信息，报价由物主补充；不宣称功能正常。

任务 C：上传无价格凭证 → 保留来源与凭证，价格未知，不写零元。

任务 D：模型断网 → 保留照片和原话，手动完成两步流程。

验收重点：少输入、少重复、少回退，同时没有新增虚构事实。上线前仍需用真实模型验证“已回答不再问”和图文冲突提醒；程序校验只能保证字段和状态边界，不能证明模型描述完全真实。
